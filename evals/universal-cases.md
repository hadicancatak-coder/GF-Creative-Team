# Universal eval cases — domain-agnostic failure classes

Give the agent the case input with **no hint about what to look for**; PASS means it raises the expected
catch unprompted. Re-run after ANY brief edit.

The **Outcome** column is the honest record. `MISSED` means a human found it and a gate did not — those
rows are why the rules above them are worded the way they are. Rows marked *codified* came from an
operating or compliance rule rather than a recorded gate failure; they are labelled so you can tell the
difference between evidence and policy.

| U51 | Code is edited and pushed, then tested — but the runtime loads an installed copy, so every run exercises the old version and the results are attributed to the new one | Verify the running artifact is the one you changed. Note the trap: a rule requiring deviations to be declared creates pressure to specify numerically so no deviation is possible — the deviation rule and the authorship boundary must be written together or the first one destroys the second | creative-director, orchestration engine | MISSED — the operator caught the resulting proportions. The directive carried eight absolute y-coordinates and 6 of 9 vertical bands landed off the spacing scale |
| U60 | The gate is handed the producer's declared deviations and the director's ruling as context, and every actionable finding is routed to the builder regardless of who owns it | Two rules. (1) A reviewer gets the brief and the artifact, nothing else — handed the defence before the evidence it reviews the defence, and will cite the ruling back at you as a reason not to look. (2) Severity is not a work order: a finding carries an owner and a scope, and only what the builder can fix on THIS artifact reaches a fix round | orchestration engine, art-director | CAUGHT in engine audit on the first live run — the art-director wrote "per the ruling I am not proposing to shorten it" about the one element it existed to contest, and the fix round routed a copywriter's undelivered deliverable plus a derivative the brief forbids building yet |
| U61 | A reviewer is pointed at the wrong target by a fallback that guesses — the engine picks the first id in a list when the explicit field is absent, and the reviewers dutifully report the wrong node as clean | A noisy wrong target is survivable; a SILENT wrong target is not. | U62 | A review role cannot reach the tool it needs to SEE the work, so it reviews from whatever it could reach. That ask is now the fallback the gate ships with |

## Scoring
A team revision passes when every case is caught by the named agent without hints. A case that used to
pass and now fails is a **regression** — a brief edit removed something load-bearing. Record it.

## The metric
Track the ratio of `MISSED` to `CAUGHT` over time. Falling means the briefs are learning.
